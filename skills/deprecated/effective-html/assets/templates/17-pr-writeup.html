Author intent

Move notification delivery off the request path.

This change makes comment creation independent of email and chat-provider latency. The API now records the comment, enqueues recipient jobs, and returns; a worker owns channel preferences, retries, and exhausted-delivery evidence.

01 · Behavior delta

Why this change exists.

A comment with many watchers can fan out into dozens of provider calls. Today those calls happen inside the mutation, so an unrelated SMTP timeout can turn a successfully stored comment into a 500 response.

Before · coupled

Write, send, then respond

  • Provider latency extends API latency
  • Failure can misreport a successful write
  • No durable retry trail after timeout
  • Staging p99: 1.4 seconds
→
After · separated

Write, enqueue, then respond

  • Provider work leaves the request path
  • Worker retries with bounded backoff
  • Exhausted jobs remain inspectable
  • Staging p99: 180 milliseconds
02 · Change tour

Read this in causal order.

The tour starts where responsibility moved, follows the enqueue call site, then closes on storage and deployment plumbing. It is intentionally not alphabetical.

01 packages/notify/src/worker.ts New · execution owner

The heart of the PR. The subscriber resolves channel preferences and delegates to adapters. Retryable errors are rethrown for queue backoff; exhausted jobs are acknowledged only after they are recorded. 

try {
  await adapters[channel].send(recipient, event);
} catch (error) {
  if (job.retryCount < retryLimit[channel]) throw error;
  await deadLetter.record(job, error);
}
02 packages/api/src/routers/comments.ts Modified · enqueue boundary

Where the latency win appears. The handler still resolves watchers, but provider calls are replaced by idempotent queue inserts. The comment transaction no longer owns delivery outcome. 

- await sendEmail(recipient, comment);
- await sendChat(recipient, comment);
+ await queue.insert({
+   name: "notify.deliver",
+   singletonKey: `${comment.id}:${recipient.id}:${channel}`
+ });
03 packages/db/migrations/0051_dead_letter.sql New · evidence store

Stores the job payload, final error, and attempt count after retry exhaustion. Rows are deliberately retained until the operating pattern is understood.

04 packages/notify/src/adapters/* + apps/worker/src/index.ts Modified · plumbing

Adapters now expose typed permanent versus retryable errors. The existing worker process registers the new subscriber; this PR adds no new deploy unit.

03 · Review focus

Where reviewer attention pays off.

01 / correctness

Retry to dead-letter boundary

Confirm an exhausted job is recorded exactly once and never rethrown into an infinite retry loop.

02 / identity

Singleton key shape

Check that comment, recipient, and channel uniquely describe one delivery intent across handler retries.

03 / scope

Deliberate omissions

Digest batching, receipts, and priority lanes stay out. They can layer on after the execution boundary is proven.
