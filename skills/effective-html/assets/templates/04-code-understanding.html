System orientation

Authentication is a request-time session lookup.

The browser carries an opaque signed cookie. Server middleware resolves it into a session, rejects missing or expired state, and exposes one trusted value to downstream handlers. Routes consume that value; they do not authenticate independently.

export function AuthProvider({ children }) {
  useEffect(() => {
    fetch("/api/session", { credentials: "include" })
      .then((response) => response.ok ? response.json() : null)
      .then(setUser);
  }, []);
}
02src/middleware/auth.tsTrust boundary

All protected routes cross this function. Missing, unknown, and expired sessions converge on the same rejection path; only a validated record enters request context.

export async function verifySession(req, res, next) {
  const id = req.signedCookies["sid"];
  const session = id ? await SessionStore.get(id) : null;

  if (!session || session.expiresAt < Date.now()) {
    return res.status(401).end();
  }
  req.ctx = { ...req.ctx, session };
  next();
}
03src/lib/sessionStore.tsLookup owner

The store owns persistence access and the read-through LRU. This keeps database knowledge out of middleware while preserving one session resolution path.

async get(id: string) {
  const cached = cache.get(id);
  if (cached) return cached;

  const row = await db.oneOrNone(SELECT_SESSION, [id]);
  if (row) cache.set(id, row);
  return row;
}
03 · Boundary and invariants

What must stay true.

Trust boundary

Untrusted cookie in.
Validated session out.

verifySession() is the only stage that changes the security meaning of the request. Everything before it is transport; everything after it assumes the attached session is valid.

  • Protected routes are mounted behind the middleware.
  • Handlers read identity from request context, never directly from cookies.
  • Expiry is enforced before context assignment.
  • SessionStore is the only caller of the sessions table.
Operational gotchas
  • The LRU is process-local. Revocation can remain visible on another worker until its 60-second cache entry expires.
  • The database driver returns expiresAt as a Date. Converting it to a string without changing the comparison would silently weaken expiry checks.
