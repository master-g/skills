02 · Finding evidence

Findings anchored to behavior.

Blocking 01

Cancel in-flight reads before the optimistic write

useOptimisticTasks.ts · L11–18 
+ onMutate: async (patch) => {
+   const prev = qc.getQueryData(key);
+   qc.setQueryData(key, applyPatch);
    return { prev };
  }
Observed sequence

Refetch → optimistic write → stale response restores the old row before the mutation settles. Add await qc.cancelQueries({ queryKey: key }) before the snapshot so the cache has one writer during the transition.

Blocking 02

Mint one idempotency key per user intent

api/tasks.ts · L13–19 
- key = crypto.randomUUID()
+ key: mutationContext.key

headers: {
  "Idempotency-Key": key
}
Failure mode

The default parameter runs for every retry. A timeout after the server commits can therefore produce a second update. Generate the key when the interaction begins and thread it through every attempt.
