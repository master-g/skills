Incident report · INC-0412 SEV-2 · April 12 · Final
Incident state

Task sync recovered after a 47-minute connection shortage.

A worker configuration reduced the database pool from 64 connections to 8. Normal load exhausted the smaller pool, producing elevated latency and 502 responses. Reverting the configuration restored service; no stored data was lost.

Current state Resolved

02 · Causal chain

The failure needed four links.

The bad value was the trigger, not the complete cause. Validation, rollout visibility, and diagnostic defaults allowed it to become a 47-minute incident.

01

Debug value persisted

A local pool limit of 8 was committed as the tier default.

02

Validation checked type only

Configuration CI accepted any positive integer, including unsafe capacity.

03

Full-fleet promotion

The value reached every worker without an availability canary.

04

Wrong rollback surface

Deploy history was visible before configuration history, delaying mitigation.

pool:
  global_max_connections: 64
  tiers:
-   sync-worker: { max_connections: 8 }
+   sync-worker: { max_connections: 64 }
