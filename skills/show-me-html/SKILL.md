# show-me-html

一个想法，一个自包含的 `.html`。无构建、无依赖、离线可开、发给谁都能直接看。

设计语言是 **shadcn/ui**：组件来自 basecoat（MIT，框架无关的 shadcn 实现），图标来自 lucide，
两者都已内置在本 skill 里，页面不联网。每一页固定带两件东西 ——

- **三态主题切换**（浅色 / 跟随系统 / 深色）：页面在谁的屏幕上都成立，不用问对方开没开深色模式。
- **复制为 Markdown**：一键把整页内容变成 Markdown，能贴进文档、粘进 IM、喂给别的模型。
  这是「做给团队看」和「做给自己看」的差别所在。

核心判断：很多交付物用页面比用散文更好。评审者点开 diff 而不是滚动一堵文字墙；
决策者把三个方案并排看到而不是靠想象；概念讲通了，是因为读者拖了一下滑块看见模型跟着动。
优化目标是**读者在这页上能做什么**，不是这页装了多少内容。

流水线：**意图 → 调度 → 材料 → 合成 → 自检 → 交付**。

## 第 1 步 · 意图（静默核对）

**用户显式调用本 skill 时（`/show-me-html ...`、「用 show-me-html 做一个」），意图已经确定：输出一个 HTML 页面。
一个问题都不要问，直接进第 2 步。**调用时跟的内容就是材料来源，按类型先取材料：

| 参数形态          | 取材方式                                                |
| ----------------- | ------------------------------------------------------- |
| URL / arxiv 链接  | 用**当前环境里可用的**抓取工具取正文，见下方选择顺序    |
| 本地路径 / 仓库   | 读文件、跑 `git log` / `git diff`                       |
| 已有 `.html` 文件 | 读进来，按本 skill 的骨架与配方重做                     |
| 只有一句话主题    | 用会话上下文里的材料；没有就按第 3 步标 `[DATA NEEDED]` |

**抓取工具不写死。** 先看本次会话实际可用的 skill 列表与 CLI，按这个顺序挑第一个可用的：

1. 用户在 CLAUDE.md 或对话里指定的抓取工具 —— 有指定就用它，不再比较。
2. 专门读该站点的 skill（站点适配器类、学术检索类），命中目标域名时优先。
3. 通用正文提取（页面转 Markdown 的 CLI 或服务）。
4. 浏览器自动化 skill —— 页面需要登录态或 JS 渲染时用。
5. 内置 WebFetch。

第一个工具失败就退到下一个，退了几层要在交付时说明。工具名以会话里列出的为准，不要凭记忆调用可能已卸载的命令。

材料取到后，配方由第 2 步的决策树选定 —— 有歧义就选覆盖面更大的那条，不回头问用户。
交付后用户再提反馈，走「反馈处理」。以下四维核对只适用于**非显式触发**（模型自行判断该出页面时）。

选配方前先确认四件事。这是背景核对，不是问卷，**永远不要四个一起问**。

| 维度     | 要确认什么               | 例子                                                               |
| -------- | ------------------------ | ------------------------------------------------------------------ |
| **任务** | 读者打开后应该能做成什么 | 在两个方案里选一个 / 批准一次改动 / 追踪分拣状态 / 感受一个交互    |
| **读者** | 谁打开，在什么场合       | 认真评审的同事 / 扫 30 秒的负责人 / 会场上看投屏的听众             |
| **交互** | 只读，还是读者要改状态   | 状态汇报只读；分拣看板必须能拖；概念讲解可能需要滑块               |
| **材料** | 已有什么，缺什么         | 贴了 diff 和笔记 = 可以开工；「做个汇报」但没有数据 = 有缺口要点名 |

- 对话里已经答过的维度，静默跳过。
- 文档类型本身就决定了的，静默跳过（复盘页的任务永远是「看懂哪里坏了、怎么不再坏」）。
- 只有当 2 个以上维度真的不清楚、**并且**答案会改变交付物时，才问一次，最多两个小问题。
- **材料从会话上下文里推断。** 用户刚跑完一个检索/抓取类 skill 就调本 skill 且没说新内容，
  材料就是上一个 skill 的产出，直接用，不要再问「用什么内容」。
- **输出语言默认简体中文。** 标题、标签、正文、图注、UI 文案都写简体中文，除非用户明确要求别的语言
  （「用英文写」是明确要求；素材是英文、对话是英文都不算）。代码、标识符、术语、原文引用保持原样。
  骨架已经是 `lang="zh-CN"`；换语言时同步改 `lang`。

**完成判据**：四个维度各有一个明确答案，其中「材料」这项能点出具体缺了哪几项。

## 第 2 步 · 调度

把任务映射到 `references/layouts.md` 里的一条配方。先匹配先赢。

| 读者要做的事                   | 配方                  | 交互                     |
| ------------------------------ | --------------------- | ------------------------ |
| 在几个实现方案里选一个         | `approach-compare`    | 只读                     |
| 在几个视觉方向里选一个         | `visual-directions`   | 主题切换即评估工具       |
| 评审一次代码改动（评审者视角） | `code-review`         | 可折叠 diff、勾选框      |
| 介绍一次代码改动（作者视角）   | `pr-writeup`          | 可展开文件卡             |
| 看懂本仓库里某条流程怎么跑     | `code-understanding`  | 可展开片段               |
| 查阅设计系统 / 风格指南        | `design-system-ref`   | 只读                     |
| 带旋钮对比组件变体             | `component-variants`  | 滑块、单选、实时 markup  |
| 感受一段动效                   | `animation-proto`     | 参数化缓动               |
| 感受一个交互机制               | `interaction-proto`   | 拖拽、键盘               |
| 现场讲一遍                     | `slide-deck`          | 键盘翻页                 |
| 拿走一组示意图                 | `svg-illustrations`   | 逐图复制源码             |
| 扫一眼项目/团队状态            | `status-report`       | 只读                     |
| 看懂一次故障与后续项           | `incident-report`     | 目录、勾选框             |
| 逐节点追一条流程               | `flowchart`           | 可点节点 → 详情面板      |
| 看懂一个功能 / API             | `feature-explainer`   | 标签页、可展开细节       |
| 看懂一个概念                   | `concept-explainer`   | 滑块驱动实时模型         |
| 评估一份实施计划               | `implementation-plan` | 只读                     |
| 分拣 / 排优先级                | `triage-board`        | 拖拽、筛选               |
| 带约束地改配置                 | `config-editor`       | 开关、依赖校验、变更预览 |
| 调文案 / 提示词并实时看结果    | `text-tuner`          | 可编辑区、变量槽高亮     |

**决策树**（先走这个，再考虑发问）：

- 读者**在选项之间做决定** → 代码/架构 `approach-compare`，视觉 `visual-directions`
- 读者**理解一次改动** → 评审者 `code-review`，作者 `pr-writeup`
- 读者**理解某样东西怎么运作** → 本仓库 `code-understanding`，产品功能 `feature-explainer`，通用概念 `concept-explainer`
- 读者**追踪工作状态** → 时间切片 `status-report`，出了什么事 `incident-report`，要建什么 `implementation-plan`，正在重排优先级 `triage-board`
- 读者**改数据** → 卡片跨列 `triage-board`，带约束的设置 `config-editor`，带反馈的文本 `text-tuner`
- **现场演讲** → `slide-deck`。看着像幻灯片、实则是给人细读的文档 → 改用 `status-report` 或 `implementation-plan`。

值得问一句的歧义只有两种：「评审页还是介绍页？」（谁驱动阅读）、「汇报还是看板？」（只读还是能改）。
**显式调用时这两句也不问** —— 前者默认 `pr-writeup`，后者默认只读的 `status-report`。

**没有配方对得上？**这是正常的 —— 这 20 条是词汇表，不是封闭集合。组合：
取结构上最近的一条当骨架，交互从 `references/interactions.md` 里拿，组件从 `references/components.md` 里拼。
「比较三种数据库 schema」就是 `approach-compare` 的骨架，每张卡里塞 `flowchart` 的 SVG 画法。

**完成判据**：选定一条配方名，并能说出它的章节顺序。

## 第 3 步 · 材料

先盘点手上有什么，再动版式：

- 任务牵扯当前仓库（「评审我的分支」「讲讲这个模块」）时，**先取材料再调度** —— 跑 `git diff`、读文件。
  页面的上限就是背后分析的上限。
- 把材料里的每一个事实、数字、人名、代码引用都落进页面。只用真数据。
- 配方要求的内容材料里没有（指标块没有指标、时间线没有时刻），**不要编**。
  要么砍掉这一块，要么标 `[DATA NEEDED: 缺什么]` 并在交付时向用户点名。
  精致页面里的编造数字比留白更糟 —— 精致会让它显得可信。

**完成判据**：材料里的每一项都有归属（进了某一节，或被明确列为缺口），没有任何数字来源不明。

## 第 4 步 · 合成

先用 2–3 句话说明计划（选了哪条配方、页面分几节、有哪些交互、材料缺什么）。这是为了透明，不是等批准，说完直接继续。

然后：

1. **拷贝 `assets/shell.html` 作为起点。** 它已含 `<head>`、防闪烁的主题脚本、与版心对齐的顶部工具条、
   主题三态切换、复制为 Markdown（单图标按钮）、右侧目录（扫描 h2/h3 自动生成，条目 ≥2 且视口 ≥80rem 时出现）、
   页面级排版 CSS，以及 `<!--SHOW-ME:CSS-->` / `<!--SHOW-ME:JS-->` 两个占位符。
   改标题（`<title>` 和 `.chrome-title` 两处），内容写进 `<main id="doc">`。
   **占位符、工具条与目录结构不要删** —— `build.py` 会检查。
2. **写 markup 前读 `references/components.md`。** 按钮、卡片、徽章、表格、提示块的外观已经在两套主题下调好；
   自己写一遍只会得到深色主题下读不了的东西。配色一律用 token
   （`var(--color-*)`、分类色 `data-tone`、图表色 `var(--chart-*)`），不写死颜色。
   **画任何 SVG 图前读 `references/diagrams.md`**：类型路由、连线六条硬规则、节点语义、复杂度预算都在那里。
3. **按配方搭结构**，见 `references/layouts.md`。材料撑不起的章节直接删 —— 短而诚实的页面胜过填满的空壳。
4. **要加交互时读 `references/interactions.md`**：拖拽、键盘翻页、旋钮联动、可点 SVG、筛选、滚动高亮都有现成代码。
5. **自包含是硬约束，只有一个例外。** 不引 CDN、不引外链图片、不引框架。图标写 `<i data-lucide="名字"></i>`
   由 `build.py` 内联，插图用内联 SVG，脚本用原生 JS。`<a href>` 指向外部可以；**加载**外部资源不行。

   例外是**骨架自带的 Google Fonts**（Merriweather / Noto Serif SC / JetBrains Mono）。
   它异步加载，取不到时静默回退到系统字体栈，页面照常可读 —— 别的外部资源没有这个性质，
   所以只有它被放行。`fonts.googleapis.com` **在中国大陆不可达**，那边的读者看到的就是兜底字体，
   这是已知且接受的降级。骨架的 `<link>` 与 `--font-*` 后半段的兜底一起构成这个保证，
   **两边都不要删**；`build.py` 会检查每个网络字体后面是否还有本地兜底、栈是否以通用族收尾。

6. **每个控件都要真的能用。** 原型里做不了的控件必须显式标注「本原型不含」。
   交互元素要能用键盘操作 —— `components.md` 里的组件都已具备，自己写的部分照 `interactions.md` 办。
7. **版心按体裁定，不要用默认值。** 骨架默认 `--page: 60rem`，那是仪表盘 / 看板 / 对比页的宽度。
   **读多写少的长文（`concept-explainer`、`feature-explainer`、`pr-writeup`、`incident-report`
   这类）一律改 `46rem`** —— 60rem 下中文一行到 55 字，读着累；46rem 落在 35 字左右。
   页里的图也跟着变紧凑，比例才对得上。写在页面自己的 `<style>` 里：`:root { --page: 46rem }`。
8. **克制就是风格。** 一屏一个强调点，留白给足，层级靠字号、留白和字重，不靠颜色。
9. **色彩只在三处出现**（调色板来自 `anthropic.design.md`，全部是 token，见 `components.md`）：
   - **分类** —— 卡片、徽章、章节写 `data-tone="clay|fig|sky|cactus|olive|heather|kraft|manilla"`，
     同一页不超过 4 个色调。分类只有一种时不上色。
   - **状态** —— `data-variant="destructive"` 等，表达语义，不做装饰。
   - **数据** —— 图表与示意图的序列色写 `var(--chart-1)` … `var(--chart-5)`。

   其余地方保持 ink 配 canvas。给标题、正文、边框加颜色属于装饰，删掉。

**完成判据**：页面在 `<main id="doc">` 里有真实内容，没有 `Acme`/`Lorem ipsum`/`{{}}` 之类的样例残留，
配方要求的每一节要么有真材料，要么被删掉，要么带 `[DATA NEEDED]` 标记。

## 第 5 步 · 自检

两道关，都要过了才算完：

**机械关** —— 跑合成与自检脚本：

```bash
python3 <skill-path>/scripts/build.py 输出文件.html
```

它把 basecoat CSS 内联进来、把用到的 lucide 图标从 sprite 里抽出来替换掉、
页面用到 tabs/dropdown-menu 等需要 JS 的组件时再内联 basecoat JS、
按页面出现的 `language-*` 内联语法高亮（只带用到的那几种语言），然后跑两组检查：

- **文本级**：自包含（除骨架的 Google Fonts 外无任何外部资源）、字体栈有本地兜底、占位符已替换、图标名有效、主题切换与复制按钮还在、
  `<meta charset>`/viewport/`lang`/`<title>` 齐全、无样例残留、`<main>` 非空、页面没有写死颜色、
  **`<main>` 的直接子元素全是 `<section>`**（间距节奏挂在 `main > section > * + *` 上，
  不包 section 的内容拿不到任何块间距，整页会挤成一团 —— 这条是 ERROR）。
- **渲染级**：装了 Chrome/Chromium 就在 500px 与 1280px 下实际渲染，检出横向溢出并点名越界元素。
  找不到浏览器时会明说这道关没跑 —— 那就自己拉一遍窄屏，**不要报「已验证」**。
  无头 Chrome 的窗口最窄只到 500px，390px 这一档只能人眼看。

**每个 ERROR 都必须修**；每个 WARN 都要逐条判断，不能一眼带过。

用户明确要求换视觉风格时加 `--style nova|maia|lyra|mira|luma|sera|rhea`，默认 `vega`。

**眼睛关** —— 脚本只测几何，读得通不通它不知道：

- 在浏览器里打开，**两种主题都切一遍**。深色下看不清的地方通常是写死了颜色。
- 数一下色调（`data-tone`）用了几种：超过 4 种就分不出组，一种也没用到就检查是不是漏了分类。
- 每张 SVG 图对照 `diagrams.md` 过一遍：没有斜线、每个标签垫了遮罩且与线有可见间隙、
  交叉处有桥、焦点色节点 ≤2、节点总数 ≤9。图例在图下方横排，不浮在绘图区里。
- 数一下正文一行有多少个中文字：超过 40 就是版心太宽，长文该用 46rem。
- 拉到 390px 看一遍：没有被挤成竖条的文字，没有贴边（这一档脚本测不到）。
- 承诺的交互都点一遍：折叠能开、拖拽能动、方向键能翻页。
- **原生控件有没有掉回系统外观**：滑块是不是变成了亮蓝色粗轨道、复选框是不是系统蓝。
  这类问题不报错、只难看，脚本只能 WARN，最终得靠这一眼。
- 图里的动效有没有在承载论点。纯装饰的动效删掉；该有方向的（失效向右流动、数据从旧到新）
  要看得出方向，均匀铺色等于把论点丢了。
- 中西混排的标题看一眼字重：中文明显比拉丁细，说明配平面没生效（多半是本机没装思源宋体，
  那就是预期内的回退）；不要在页面里另写 `--font-*` 去「修」它。
- 每张交互图的图头都要有一句操作提示（「拖动这个循环」），图注要是一句能独立成立的结论 ——
  没提示的图，读者当它是静态图片。
- 视口 ≥1280px 时确认右侧目录出现：滚动时指示条滑动跟随当前节（页顶无激活、页底落在最后一项），
  点条目平滑跳转；<1280px 目录整块消失。两档下工具条左右缘都要与内容对齐。
- 点一次复制按钮（剪贴板图标，点后变对勾），把结果粘出来看：标题层级对不对、表格完整不完整、
  工具条、目录和筛选器有没有混进去（应该被 `data-md-skip` 挡掉）。
- 通读一遍：只看各级标题，故事应该是通的。
- 没有 AI 味的填充 —— 复述标题的段落、为了对称而存在的空章节、编造的统计数字。

JavaScript 不平凡时，顺手看一眼浏览器控制台有没有报错。

**完成判据**：`build.py` 返回 0；两种主题、两种宽度都亲眼看过；Markdown 导出结果贴出来验证过一次。

**已知缺口**：没有自动的对比度检查。骨架调色板里的每一对前景/背景都在两种主题下实测过（最低 4.6:1），
组件自身的对比度由 basecoat 保证，`build.py` 会对写死的颜色报 WARN ——
但页面自己搭出来的颜色组合（色调面上再叠一层、自绘 SVG 的填充色）仍然只能靠眼睛关拦。
截图可以用已装的 `ego-browser` skill。

## 第 6 步 · 交付

- 存成描述性的 kebab-case 文件名（`auth-refactor-review.html`，不是 `output.html`），放在工作目录或用户指定处。
- 汇报三件事：文件路径、先看哪里、还剩哪些 `[DATA NEEDED]` 缺口。
- 可以提议打开（macOS：`open 文件.html`），但不要替用户打开。

## 反馈处理

视觉反馈含糊时（「太挤了」「不太对」），**报当前值再给方案**：
「卡片内边距现在是 1rem、网格间距 1rem，放宽到 1.75rem / 1.25rem，还是行高（1.7）显得紧？」
不要只说「我调一下间距」而不点名属性和新数值。

反馈是关于内容的（「这没说到点子上」），回第 1 步：错的通常是「任务」这一维，不是 CSS。

## 不适用

- 要印出来的文档 —— 简历、一页纸、白皮书、信函、PDF 讲义、落地页 → **kami**
- 带路由、构建或后端的多页站点
- 用户要的是 React 项目和真 shadcn 组件源码 → **shadcn** skill
- 一句话就能答清楚的事（一个事实不需要一个页面）

## 文件清单

- `assets/shell.html` — 页面骨架（含右侧目录）。每次都从它起手，不要从零手写 `<head>`。
- `references/components.md` — basecoat 组件词表与精确 markup、设计 token。**写 markup 前必读。**
- `references/layouts.md` — 20 条配方的章节顺序与组件选择。读选中的那一条。
- `references/interactions.md` — 拖拽、键盘翻页、旋钮联动、可点 SVG 等现成代码。加交互时读。
- `references/diagrams.md` — SVG 图的类型路由、连线六规则、节点语义处理、复杂度预算、无障碍契约。**画任何图前必读。**
- `scripts/build.py` — 合成（内联 CSS/图标/JS/语法高亮）+ 自检。每次输出都要跑。
- `assets/vendor/` — basecoat CSS（8 套风格包）、basecoat JS、lucide sprite、
  语法高亮（`shj/`，@speed-highlight/core，CC0）。
  **不要把这些文件读进上下文**，全部由 `build.py` 拼接。
