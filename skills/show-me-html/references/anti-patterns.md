# 反模式名册 — 页面层与骨架层

这份名册收录 **`build.py` 检查抓不到、靠生成时识别** 的失败。每条有名字、识别特征、当页修法。
「状态」一列记录生命周期：`未编码` →（毕业为 `build.py` 检查）→ `已检查` →（骨架根治后）→ `已根治`。
命名一个失败，agent 识别并回避它的可靠性高得多；编码过的失败倾向于不再出现。

生成页面时过一遍；改完骨架或检查后，把对应条目的状态推进一格。

| #   | 名字         | 状态     | 识别特征                                                                                                     | 当页修法                                                                                                                       |
| --- | ------------ | -------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 统计孤儿     | 部分根治 | 统计数字写成标题标签。目录孤儿已由骨架根治；数字若仍用 `h3`，导出还是会出现孤立的数字标题。                  | 数字用带类段落（如 `<p class="stat-num">7</p>`），标题层留给真正的节。                                                         |
| 2   | 双头导出     | 已根治   | `#doc` 首个可见块不是 `h1`（常见：eyebrow 段落在前）。骨架导出器已改为：正文含一级标题即不拼 `<title>`。     | 无需当页修法；多个 `h1` 会被 build.py 拦（ERROR）。                                                                            |
| 3   | 隐式轨道溢出 | 已检查   | 自造 `display: grid` 容器不写 `grid-template-columns`。隐式 auto 轨道按内容 max-content 计宽，窄屏横向溢出。 | 显式写列模板：单列 `1fr`，多列抄 layouts/interactions 里带 `minmax(min(100%,…),…)` 的写法。 build.py 对无模板的 grid 报 WARN。 |

三条的共同来源：**自造容器**。layouts.md 与 interactions.md 给出的每个 grid 示例都带显式模板；
偏离示例自己搭容器时，先查这张表。

## 与维护规则的关系

发现新失败时的落点判断（改页面、改骨架、加检查、写指引）见 `MAINTENANCE.md` 的纠正路由。
本名册只回答两个问题：生成时「我是否正在犯已知错误」；维护时「哪个失败该毕业成检查」。

状态推进记录：

- 2026-09-01 三条登记（未编码）。
- 2026-09-01 P1：#2 骨架根治（导出器 hasH1 判断）；#1 目录面骨架根治（TOC 生成器跳过
  `.card/.fig-box/.alert/.item` 等组件容器内的标题）；#3 毕业为 build.py WARN（`check_grid_tracks`），
  首跑即命中存量案例一处。#1 的导出面不毕业为检查 —— 卡片内 `h3` 是官方 markup
  （components.md 的 `.card > header > h3`），静态无法区分「卡片标题」与「统计数字」，靠本名册识别。
