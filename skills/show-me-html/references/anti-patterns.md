# 反模式名册 — 页面层与骨架层

这份名册收录 **`build.py` 检查抓不到、靠生成时识别** 的失败。每条有名字、识别特征、当页修法。
「状态」一列记录生命周期：`未编码` →（毕业为 `build.py` 检查）→ `已检查` →（骨架根治后）→ `已根治`。
命名一个失败，agent 识别并回避它的可靠性高得多；编码过的失败倾向于不再出现。

生成页面时过一遍；改完骨架或检查后，把对应条目的状态推进一格。

| #   | 名字         | 状态   | 识别特征                                                                                                                                                                                                 | 当页修法                                                                                    |
| --- | ------------ | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1   | 统计孤儿     | 未编码 | 统计数字写成 `.card header` 里的 `h2`/`h3`。右侧目录出现「7」「91 → 39」这类条目；「复制为 Markdown」出现孤立的数字标题。                                                                                | 数字改用带类的段落（如 `<p class="stat-num">7</p>`），标题层留给真正的节。                  |
| 2   | 双头导出     | 未编码 | `#doc` 首个可见块不是 `h1`（常见：eyebrow 段落排在标题前）。导出器检测不到行首 `#`，把 `<title>` 也拼成一级标题，结果两个 `#`。                                                                          | 把 `h1` 放进第一个块，或给前置的元信息段落加 `data-md-skip`。                               |
| 3   | 隐式轨道溢出 | 未编码 | 自造 `display: grid` 容器不写 `grid-template-columns`。隐式 auto 轨道按内容 max-content 计宽，文档宽超出视口（实测 500px 视口被撑到 596px）。`build.py` 渲染关报「横向溢出」，越界元素正是这个自造容器。 | 显式写列模板：单列 `1fr`，多列抄 layouts/interactions 里带 `minmax(min(100%,…),…)` 的写法。 |

三条的共同来源：**自造容器**。layouts.md 与 interactions.md 给出的每个 grid 示例都带显式模板；
偏离示例自己搭容器时，先查这张表。

## 与维护规则的关系

发现新失败时的落点判断（改页面、改骨架、加检查、写指引）见 `MAINTENANCE.md` 的纠正路由。
本名册只回答两个问题：生成时「我是否正在犯已知错误」；维护时「哪个失败该毕业成检查」。
