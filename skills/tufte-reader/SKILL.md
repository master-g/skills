# tufte-reader

把材料做成一份**读本**：单个离线 HTML 文件，正文栏加页边注释的 Tufte 版式，书的架构（扉页、目录、章、章末出处）。公式在构建时编译成 MathML。

用户调用即表示要读本。材料缺失、无法取得时才提问。

## 1. 取材，列结构清单

按材料来源取全文：

- **arXiv**：优先取 LaTeX 源 `https://arxiv.org/e-print/<id>`（tar.gz，含公式、脚注和图文件），其次 `https://arxiv.org/html/<id>`，最后才用 PDF。源码里的 PDF 图转成 PNG（macOS 用 `sips -s format png a.pdf --out a.png`，其他系统用 `pdftoppm -png`）。
- **其他网页**：用当前环境可用的正文提取工具，图片下载到输出目录的 `figures/`。
- **PDF**：提取文本后按原文重写公式为 LaTeX；图片用 `pdfimages` 取出，或截取对应区域。
- **本地文件、仓库文档**：直接读。

处理方式有三种：

- **全文忠实翻译**：单篇外文材料的默认做法。
- **整理**：用户说「整理」「导读」「精简」，或材料已是中文、需要重新组织，或是多份材料合成一本。按 [行文](references/style.md) 的「整理与组织」处理。
- **原创撰写**：用户给的是主题（「写一本讲 X 的读本」），没有要逐段对应的原文，读本的章节和文字都由你来写。按 [行文](references/style.md) 的「原创撰写」处理，资料仍按上面的办法取全文。

完成标准：拿到完整原文，并写下**结构清单**：各级标题、图、表、块级公式、脚注、参考文献各有多少条。按出现次数计数（`grep -o '\\sidenote' | wc -l`），`grep -c` 只数行，同一行有两条注时会少算。原创撰写没有原文可数，结构清单改为动笔前的计划：每章的标题、节数，以及图、表、块级公式、注释、引用文献的计划条数。

## 2. 定术语表

读完全文（原创撰写时是读完资料、列好章节计划）后，列出标题里出现的、全文出现两次以上的术语，各定一个译名。术语表留在工作区，不进页面。

完成标准：清单里每个术语只有一个译名。

## 3. 逐章写读本

把 `assets/shell.html` 复制到输出路径（用户指定的位置，否则当前目录；文件名取原文标题的 kebab-case，原创撰写取书名），按 [标记契约](references/markup.md) 和 [行文](references/style.md) 写。

一次写一章，写完一章再写下一章。

完成标准：每章的段落、脚注、图、表、公式都和原文一一对应（整理模式下，删掉的部分已在该章译注里写明）。原创撰写时，每写完一章就和结构清单里该章的计划数对一遍，有出入就改正文或改清单，并记下原因。

## 4. 构建与核对

```sh
python3 <skill-path>/scripts/build.py 页面.html
```

构建需要 node，用来编译公式。修掉所有 ERROR，逐条判断 WARN。

把构建输出的「统计」行和结构清单对照，每一处差异都要说得出原因。例如：原文的页边图计入「页边图」而不是「图」；原文第四级标题改成了 `newthought`，所以 h3 变少；原作者脚注按分流规则分成了边注和章末脚注，两者合计应等于原脚注数，另加译注条数。

「行内公式」只统计编译成功的。正文里留下成对的 `$` 时构建报 ERROR 并给出上下文，按提示改完再构建。

完成标准：0 个 ERROR，统计与结构清单的每处差异都能解释。

## 5. 打开与交付

最后一次构建加 `--open`，检查通过后会在默认浏览器里打开。用户要求不打开时去掉这个参数。

交付说明包括：文件路径；处理方式（全译、整理或原创撰写）；删节和未译部分；仍然存疑的地方，例如取不到的图、拿不准的译法。原创撰写还要写明哪些事实、数字、公式对照过资料原文，哪些没有，与扉页读本说明一致。浏览器打不开时，报告路径并说明未做浏览器检查。

## 修改本技能

改了 `assets/tufte.css`、`shell.html`、`shell.js` 或 `scripts/` 之后，运行 `python3 -m unittest discover -s <skill-path>/tests`。然后把 `assets/specimen.html` 复制到临时目录并构建，在 1280px 和 390px 两种宽度、明暗两种主题下各看一遍。specimen 包含全部元素，是这套版式的回归样张。

无头 Chrome 的窗口最窄 500px，`--window-size=390,…` 截出的是按 500px 排版、右侧被裁掉的图。看 390px 要用能设置视口的浏览器工具，或者写一个只含 `<iframe src="specimen.html" width="390" height="844">` 的外层页面，对外层页面截图。
