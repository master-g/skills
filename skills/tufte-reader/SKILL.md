# tufte-reader

把材料做成一份**读本**：单个 HTML 文件，正文栏加页边注释的 Tufte 版式，书的架构（扉页、目录、章、章末脚注、参考文献）。公式在构建时编译成 MathML。内容、样式和脚本全部内联，离线可读；只有字体（西文 STIX Two Text 与配套的公式字体 STIX Two Math、中文思源宋体）联网时从 jsDelivr 加载，离线或加载失败时回退系统字体。

用户调用即表示要读本。材料缺失、无法取得时才提问。

## 1. 取材，列结构清单

输出路径是用户指定的位置，否则当前目录。页面文件名默认是 `YYYY-MM-DD-<标题>.html`：日期取动笔当天的本机日期（运行 `date +%F`），标题部分取原文标题（原创撰写取书名）的英文 kebab-case，中文标题先意译成简短英文，例如 `2026-10-16-attention-is-all-you-need.html`。用户给了完整文件名时照用；续写或修订已有读本时沿用原文件名；工作区里有 `src/` 的读本是分章派发写成的，改 `src/` 里的片段后运行 `assemble.py`，不改页面（见 [分章派发](references/dispatch.md)）。页面旁建**工作区** `<页面名>.work/`：取到的原文、结构清单 `outline.md`、术语表 `glossary.md` 都放在这里，不进页面。

按材料来源取全文：

- **arXiv**：优先取 LaTeX 源 `https://arxiv.org/e-print/<id>`（tar.gz，含公式、脚注和图文件），其次 `https://arxiv.org/html/<id>`，最后才用 PDF。源码里的 PDF 图转成 PNG（macOS 用 `sips -s format png a.pdf --out a.png`，其他系统用 `pdftoppm -png`）。
- **其他网页**：用当前环境可用的正文提取工具，图片下载到输出目录的 `figures/`。来源或许可不明的图、简单的示意图不照搬，按 [行文](references/style.md) 的「重画原图」处理。
- **PDF**：提取文本后按原文重写公式为 LaTeX；图片用 `pdfimages` 取出，或截取对应区域。
- **本地文件、仓库文档**：直接读。

处理方式有三种：

- **全文忠实翻译**：单篇外文材料的默认做法。
- **整理**：用户说「整理」「导读」「精简」，或材料已是中文、需要重新组织，或是多份材料合成一本。按 [行文](references/style.md) 的「整理与组织」处理。
- **原创撰写**：用户给的是主题（「写一本讲 X 的读本」），没有要逐段对应的原文，读本的章节和文字都由你来写。按 [行文](references/style.md) 的「原创撰写」处理，资料仍按上面的办法取全文。

完成标准：拿到完整原文，并写下**结构清单**：逐章列出各级标题、图、表、块级公式、脚注各有多少条，末尾是全书合计和参考文献条数。原文的段落能机械数出时（HTML 的 `<p>`、Markdown 以空行分段），每章再列段落数；LaTeX 和 PDF 原文数不准，不列。按出现次数计数（`grep -o '\\sidenote' | wc -l`），`grep -c` 只数行，同一行有两条注时会少算。原创撰写没有原文可数，结构清单改为动笔前的计划：每章的标题、节数，以及图、表、块级公式、注释、引用文献的计划条数，连同该章图、表、式的编号区间。用户要求配题图时，结构清单另列题图：扉页用哪一幅，哪几章配、各用哪一幅（选法见 [题图](references/plates.md)）。

## 2. 定术语表

读完全文（原创撰写时是读完资料、列好章节计划）后，列出标题里出现的、全文出现两次以上的术语，各定一个译名，写进工作区的 `glossary.md`。

完成标准：清单里每个术语只有一个译名。

## 3. 逐章写读本

按 [标记契约](references/markup.md) 和 [行文](references/style.md) 写。先按下面的两种写法定下用哪一种，再写扉页和参考文献，然后写各章。

用户要求配题图时，按 [题图](references/plates.md) 选图、取图：扉页题图随扉页写，章首题图在各章写完后统一放（分章派发时等各章片段返回后，放进 `src/` 里对应的片段，扉页题图放进 `head.html`）。

各章的写法按章数和环境二选一：

- **分章派发**：全书三章以上、环境里有子 agent 工具时，每章交给一个子 agent 写成片段，放在工作区的 `src/`，用 `scripts/assemble.py` 拼成页面。扉页和参考文献也写成 `src/` 里的片段，不在输出路径手建页面。按 [分章派发](references/dispatch.md) 做。
- **逐章自己写**：其余情况。把 `assets/shell.html` 复制到输出路径，在这个页面里一次写一章，写完一章再写下一章。

完成标准：每章的段落、脚注、图、表、公式都和原文一一对应（整理模式下，删掉的部分已在该章译注里写明）。原创撰写时，每写完一章就和结构清单里该章的计划数对一遍，有出入就改正文或改清单，并记下原因。分章派发时，页面里章的数目和顺序还要与结构清单一致。

## 4. 构建与核对

```sh
python3 <skill-path>/scripts/build.py 页面.html
```

分章派发的读本改用 `python3 <skill-path>/scripts/assemble.py <源目录> -o 页面.html`：它拼接片段后自己调用 `build.py`，参数照传。

构建需要 node，用来编译公式和 Mermaid 图。修掉所有 ERROR，逐条判断 WARN。

把构建输出的「统计」行和结构清单对照，每一处差异都要说得出原因。合计对不上时加 `--by-chapter` 重跑，它在「统计」行之后每章再打印一行，逐章找出差在哪里。例如：「段落」只数各章正文里的段落，列表、引文、图、表和章末脚注里的不算；原文的页边图计入「页边图」而不是「图」；原文第四级标题改成了 `newthought`，所以 h3 变少；原作者脚注按分流规则分成了边注和章末脚注，两者合计应等于原脚注数，另加译注条数；分步图同时计入「图」和「分步图」，「帧」是各分步图的步数之和；题图单独计入「题图」，不算在「图」里，它的图注计入「旁注」；插图里的公式标签单独计入「图内公式」，不算在「行内公式」里。

「行内公式」只统计编译成功的。正文里留下成对的 `$` 时构建报 ERROR 并给出上下文，按提示改完再构建。

完成标准：0 个 ERROR，统计与结构清单的每处差异都能解释。

## 5. 打开与交付

最后一次构建加 `--open`，检查通过后会在默认浏览器里打开。用户要求不打开时去掉这个参数。

交付说明包括：文件路径；处理方式（全译、整理或原创撰写）；删节和未译部分；仍然存疑的地方，例如取不到的图、拿不准的译法。原创撰写还要写明哪些事实、数字、公式对照过资料原文，哪些没有，与扉页读本说明一致。浏览器打不开时，报告路径并说明未做浏览器检查。

改这个技能的样式、骨架或脚本之前，先读 [维护](references/maintaining.md)。
