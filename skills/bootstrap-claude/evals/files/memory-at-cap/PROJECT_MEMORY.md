## 已验证的事实

<!-- 追加：确认过的决策和约束，每条一行：结论 + 原因 + 来源。同主题改写既有条目，不追加第二条。 -->

- [2026-03-02] 定时任务的 cron 表达式按 `CRON_TZ=Asia/Shanghai` 解释，CronJob 的 `timeZone` 字段在集群 1.29 上已经稳定可用，不用再按 UTC 手算偏移。来源：平台组 2026-03 的集群升级公告。
- [2026-03-07] 人民币和港币金额按银行家舍入保留两位，和清算系统一致；日元没有辅币，按 0 位小数结算。各币种的小数位在 `currency_exponent` 表里配，新增币种先在这里登记。来源：财务 2026-03 的确认邮件。
- [2026-03-12] 发布不要手动 `git tag` 再推送，每次必须走 `make release-tag VERSION=x.y.z`：它先给 CHANGELOG 的「未发布」盖上版本号和日期，再打签名 tag，部署流水线只接受签名 tag，手打的 tag 会卡在审批。来源：发布 1.2.0 时卡了半天。
- [2026-03-16] 手续费先逐笔算到厘、汇总后再一次性舍入到分（`fee_precision`=3）；逐笔舍入到分会让大商户每月差出几十元，商户来问过两次。来源：手续费精度的讨论票 #156。
- [2026-03-21] 招商银行的结算文件用竖线分隔、GB18030 编码，文件名形如 `CMB_SETTLE_20261101_001.txt`，末尾序号从 001 开始每天重置。来源：招行对接群 2026-03 发来的样例文件。
- [2026-03-26] 对账分两段：先把银行回单和结算明细各自按 `recon_match_key`（商户号 + 结算日 + 批次号）分组求和，组内金额相等就算平；只有对不平的组才逐笔按交易流水号匹配，剩下的写进差错表。所以正常一天只有几百次组级比较、几秒跑完；一旦出现一个大额差错组，那一组会退化成逐笔比较，耗时从秒级涨到分钟级，这是正常现象，不是 SQL 变慢，不用去加索引。差错组的金额阈值在对账配置里，超过 5 万元的组会额外发一封邮件给财务值班。来源：2026-03 对账耗时的排查记录和对账设计草稿，财务和 DBA 都看过。
- [2026-03-31] 建设银行要求数据文件传完之后再上传一个同名的空标志文件（后缀由 `ccb_flag_suffix` 配置，默认 `.ok`），银行看到标志文件才取数，顺序反了会读到半个文件。来源：建行 SFTP 对接说明 v1.4。
- [2026-04-04] CI 里的 `bank-sandbox-e2e` job 临时跳过，等 #212（沙箱银行证书续期）合并后恢复；#212 已合并，job 已恢复运行，这条已经不再适用。
- [2026-04-09] SFTP 推送失败按指数退避重试，`push_retry_max`=5，间隔从 30 秒起翻倍；银行网关在整点前后约 2 分钟拒绝新连接，5 次刚好覆盖这个窗口。来源：2026-04 推送失败日志的统计。
- [2026-04-14] 交通银行批量代付文件用 `bocom_fixed_320` 格式：每行固定 320 字节，金额右对齐、左补零、单位为分，户名不足的部分补全角空格。来源：交行企业网银接口文档 v2.3 的「批量代付」一章。
- [2026-04-19] 商户 webhook 通知失败最多重试 8 次，总跨度约 24 小时（`webhook_retry_schedule`），超过就进人工补发队列；商户普遍要求当天收到，所以没再延长。来源：商户运营 2026-04 的需求。
- [2026-04-24] 银行回单的到账日期和我们的结算日不总在同一天：工行、建行 T+1 到账，招行同日到账，农商行遇节假日顺延到下一个工作日。对账时用 `recon_value_date_offset` 按各银行的配置把回单日期映射回结算日；节假日表取自 holidays-cn 包每年 12 月发布的版本，包没升级时节后第一天的对账会整批对不上，差错表里全是「找不到对应结算日」，升级包后对那几天重跑对账即可，差错会自动消掉。调休上班的周末算工作日，这一点 holidays-cn 已经处理，不用另配。来源：2026-02 春节前后的差错处理记录和财务的复核结论。
- [2026-04-28] 生产部署由 Argo CD 同步 `deploy/prod` 目录，镜像 tag 由 CI 写回 `values-prod.yaml`；直接改集群里的 Deployment 会在 3 分钟内被 Argo 改回来。来源：平台组的部署文档。
- [2026-05-03] 预发环境 `settlekit-staging` 接的是银行沙箱，沙箱每天 2:00–4:00 重置数据，这段时间推送一律返回 550，属正常现象。来源：银行沙箱的维护公告。沙箱返回的回执格式和生产一致，可以用来验证回执解析，但金额和户名是随机生成的，不能拿来核对金额。
- [2026-05-08] `SETTLE_BATCH_SIZE` 临时从 1000 调到 200，用来绕过招行网关的 30 秒上传超时；改成流式上传（#241）之后已恢复默认 1000，这个临时值已被取代。
- [2026-05-13] SQLAlchemy 锁在 `sqlalchemy<2.1`：2.1 的 `Row` 类型变化会让 mypy strict 报 60 多处错误，等 2.1 稳定后单独开票迁移。来源：依赖升级评估票 #198。迁移时顺带把 `Row` 的用法换成 `.mappings()`，可以一次清掉大部分类型错误。
- [2026-05-17] psycopg 的二进制 wheel 在 Alpine 上装不了，所以基础镜像用 `python:3.12-slim-bookworm`；换基础镜像前先确认里面的 libpq 版本。来源：2026-05 镜像瘦身时踩过。
- [2026-05-22] 直连商户号以 M10 开头，代理商下挂商户以 A20 开头（`merchant_prefix_map`），两类的结算账户分别在我们和代理商那边，出文件时分两批。来源：业务方 2026-05 的说明。
- [2026-05-27] 对账允许的金额误差由 `RECON_TOLERANCE_FEN` 控制，单位是分，默认 0。跨境商户是例外：外币结算经过银行换汇，银行按自己的牌价逐笔舍入到分，我们按中间价算，两边每笔可能差 1 分，所以港币和美元商户配成 1。误差按笔累计，一批 300 笔的港币结算最多允许差 3 元，超过才进差错表；财务每月抽查一次这类差额，至今没有发现超过阈值的。人民币商户保持 0，任何一分钱的差额都要进差错表人工看，这是财务明确要求的。来源：财务 2026-05 的确认邮件和跨境上线评审纪要。
- [2026-06-01] 港币商户的结算账户在香港本地行，汇款报文由 `mt103_builder` 按 SWIFT MT103 生成，不走国内定长格式；目前只有 12 家，每笔都要人工复核后放行。来源：跨境业务的上线评审纪要。
- [2026-06-05] 结算日跳过法定节假日，假日安排放在 `settle_calendar` 表，每年国务院公布次年安排后手工导入；漏导时元旦当天会照常出文件，被银行整批退回。来源：2026 年元旦的退回事件。
- [2026-06-10] 银行 SFTP 私钥不要写进 `.env`、日志或 issue，每次都用 `vault kv get secret/settlekit/sftp` 按需拉取、只放进程内存：有人把私钥贴进过 issue，三家银行的公钥白名单全部重签，花了两周。
- [2026-06-15] 结算任务结束后往 Prometheus 推 `settle_job_duration_seconds`，告警阈值 20 分钟；超时通常是某家银行 SFTP 慢，不是我们的查询慢。来源：2026-06 三次告警的复盘。
- [2026-06-20] 补充交行批量代付格式那条：文件末行是汇总行，`trailer_crc32` 对前面所有明细行（不含换行符）算 CRC32，写成 8 位大写十六进制；缺了或算错整批退回，不会逐行报错。来源：第一次上线被退回的回执。
- [2026-06-25] 生成结算文件的查询走主库（`SETTLE_DB_READONLY=false`）：只读副本平时延迟不到 1 秒，月末高峰可达 30 秒，读副本会漏掉最后几分钟的交易。来源：DBA 2026-06 的监控截图。
- [2026-06-29] 出文件前先比对明细合计和汇总行（`check_totals`），对不上就中止整批，宁可晚出也不出半份文件；这是一次漏行事故之后加的，银行对错误文件的退回要人工处理一天。来源：事故复盘。
- [2026-07-04] 结算单 PDF 用 WeasyPrint 渲染，中文字体固定为 `NotoSansCJKsc-Regular`，容器里没装这个字体时中文会显示成方块。来源：结算单乱码票 #174。字体随基础镜像一起装，镜像构建时会检查字体文件是否存在，缺了构建失败。
- [2026-07-09] 差错表每条记录的 `break_status` 有三种：open 表示待人工处理，matched_late 表示后续回单补到后自动平掉，written_off 表示财务确认核销。自动平账任务每天 10:00 和 16:00 各跑一次，只处理 open 状态、且回单日期在 7 天内的记录；超过 7 天的只能由财务在后台手工核销，系统不再自动匹配，这是审计的要求，防止长期挂账被悄悄抹平。核销时要填原因，原因会进月度审计报表，空原因的核销请求会被后台拒绝。来源：2026-07 内审的整改意见和后台核销功能的需求单。
- [2026-07-14] 商户 API 用 HMAC-SHA256 签名，时间戳允许 ±300 秒漂移（`sig_max_skew`），超过返回 401；有几家商户服务器时钟不准，处理办法是让对方装 NTP，不放宽窗口。来源：安全评审意见。
- [2026-07-18] 工商银行 SFTP 主机维护期间临时改连备用地址 `sftp-bak.icbc-gw.internal`，推送失败率从 9% 降到 0；维护已结束，配置已切回主地址，这条已作废。
- [2026-07-23] 银行文件里的户名超长要按字节截断：GB18030 下一个汉字占 2 字节，`truncate_gb_bytes` 遇到截在半个字上时会退一个字节。来源：户名乱码票 #163。UTF-8 输出的银行（目前只有浦发）不走这个函数，按字符截断即可，浦发的字段长度也是按字符定义的。
- [2026-07-28] `.github/workflows/ci.yml` 里的 Postgres service 版本和生产一样是 16.4，CI 通过基本能代表生产上的 SQL 行为；两边版本曾经不一致，CI 绿了生产仍出过语法差异。来源：2026-07 升级 16.4 的记录。
- [2026-08-02] mypy 用 strict，paramiko 没有自带类型，用 `types-paramiko` 存根包；存根的主版本要和 paramiko 对齐，否则会报一串 attr-defined。来源：2026-08 升级 paramiko 3.4 时遇到。
- [2026-08-07] 结算文件按商户并发生成，`SETTLE_WORKERS`=8 是连接池 20 减去 API 占用之后的上限，再调高会在月末把连接池打满，API 跟着超时，要调先找 DBA 扩连接池。来源：2026-08 的压测报告。
- [2026-08-11] 银行 SFTP 只接受 RSA 4096 和 ed25519 密钥；农商行的老网关只认 `ssh-rsa`，要在 paramiko 的 `disabled_algorithms` 里给它单独放开，别的银行不放。来源：农商行对接时的握手日志。
- [2026-08-16] 商户可以在后台把结算周期设为 T+1 或 T+7（`settle_cycle_days`）；T+7 的商户每周一出一份合并文件，不是每天一份。来源：产品需求文档 PRD-88。周期变更从下一个结算周期开始生效，当期已累计的交易仍按旧周期出文件，避免一笔交易被结算两次。
- [2026-08-21] 老表 `legacy_payouts` 是早期用 Decimal 按元存的付款记录，现在只读不写，新数据都在按分存储的表里，等迁完历史数据后下线。来源：2026-08 的数据模型评审。
- [2026-08-26] 给财务的 Excel 汇总用 openpyxl 写，单个 sheet 超过 1,048,576 行会被 Excel 截断，所以按 `xlsx_rows_per_sheet`=900000 拆 sheet。来源：财务 2026-08 打开大文件时发现缺行。
- [2026-08-30] 银行退票（户名不符、账户冻结）通过次日的 `refund_notice` 文件回传，状态回写到结算单并通知商户；退票不自动重推，要商户改完资料后人工重新发起。来源：与各行确认的退票流程。
- [2026-09-04] 商户开户行的联行号存在 `cnaps_code` 字段，12 位；人行每季度更新一次联行号库，用了过期联行号的跨行代付会被退。来源：跨行代付被退票 #187。联行号库的更新由运维下载后导入，导入脚本会列出失效的联行号和受影响的商户，交给商户运营逐个联系。
- [2026-09-09] 运行环境由 `SETTLEKIT_ENV` 区分（dev / staging / prod），启动时校验必填配置，缺项直接退出、不带默认值，避免预发漏配时静默用上生产的默认值。来源：一次预发连到生产 SFTP 的事故。
- [2026-09-14] 老商户的结算文件仍是逗号分隔的 CSV（名单在 `legacy_csv_merchants`，37 家），新商户统一用银行格式；名单只减不增。来源：商户运营 2026-09 的决定。迁移前提前一个月通知商户。
- [2026-09-18] 数据库连接走 PgBouncer 的 transaction 模式，所以代码里的锁实现成 `pg_advisory_xact_lock`，事务结束自动释放；会话级 advisory lock 在这种模式下会随连接被复用到别的请求上。来源：DBA 的连接池说明。
- [2026-09-23] alembic 的 env.py 里设了 `compare_type=True`，否则改列类型时 autogenerate 检测不到变化，生成的迁移是空的。来源：迁移漏改票 #131。即使开了它，autogenerate 对服务端默认值的变化仍然不敏感，改默认值的迁移要手写。
- [2026-09-28] 农业银行的结算文件首行要写文件头 `ABC_HDR_V3`，含商户总数和总金额，文件头和明细用同一种编码；缺文件头时农行不回执，只能等超时后打电话确认。来源：农行对接说明 2026 版。
- [2026-10-03] 美元商户按美分结算，汇率取当天 10:00 的中间价快照（`fx_snapshot_at`），同一天内重推沿用同一个快照，两次推送的金额才一致。来源：跨境业务上线评审纪要。
- [2026-10-08] 商户改结算账户有 24 小时冷静期（`account_change_hold_hours`），期间结算仍打到旧账户，用来防盗号改卡；商户投诉过，风控不同意缩短。来源：风控 2026-07 的书面意见。
- [2026-10-12] 结算文件先落盘到 `/var/lib/settlekit/outbox`，推送成功后保留 30 天再清理，银行要求追溯时可以原样重发，不用重新生成。来源：运维和各行的约定。
- [2026-10-17] 各银行 SFTP 的主机指纹固定在 `known_hosts.d/banks` 里，指纹一变推送会全部失败；银行换证书一般提前一周发邮件通知，邮件转到运维值班邮箱。来源：2026-08 建行换证书的经过。
- [2026-10-22] HTTP 客户端统一用 httpx，超时 `HTTPX_TIMEOUT_SECONDS`=10，商户 webhook 单独放宽到 15 秒；以前默认不设超时，一个 worker 卡了一整夜。来源：2026-05 的事故复盘。
- [2026-10-27] 本地联调用 `bank-sim` 容器模拟各行 SFTP，当前和预发沙箱同为 2.4 版；两边版本不同时文件格式的校验规则也不同，出现过本地通过、预发不通过的情况。来源：联调问题票 #205。
- [2026-10-31] 跨境商户的结算币种以签约币种为准（`contract_currency`），交易币种不同时先换汇再汇总，一张结算单里不出现两种币种，代码里遇到混币种直接报错。来源：跨境业务评审。
- [2026-11-05] 依赖升级每月第一周集中做，`renovate.json` 把小版本升级合成一个 PR；银行相关的包（paramiko、cryptography）单独成 PR，因为要在沙箱里跑一遍推送。来源：团队 2026-10 的约定。
- [2026-11-10] 日志和 Sentry 里的银行卡号由根 logger 上的过滤器 `mask_account` 统一打码成只留后 4 位，新模块不用另配；这是 PCI 审计的整改项，审计每半年抽查一次日志。来源：2026-09 的审计报告。

## 失败尝试

<!-- 追加：走不通的路径及原因，每条一行。 -->

- [2026-03-02] 试过用 `asyncssh` 替换 paramiko 做并发推送，招行网关对同一账号最多允许 2 个并发会话，多了直接拒绝登录，收益为零，放弃。瓶颈在银行侧的会话数上限，不在我们的 I/O 模型，换库解决不了。来源：2026-03 与招行技术支持的电话确认。
- [2026-03-14] 试过把对账改成按交易流水号全量逐笔匹配（`recon_full_scan` 分支），想省掉组级汇总这一层。结果一天 40 万笔回单要和 40 万笔明细做哈希连接，Postgres 临时文件涨到 18 GB，跑了 50 分钟还没结束，而两段式的版本只要 40 秒；而且银行回单里约 2% 的流水号是截断的，逐笔匹配反而多出几千条假差错，财务一天看不完。放弃，保留两段式，截断流水号的回单只在组级对不平时才做模糊匹配，而且模糊匹配的结果只当建议、不自动平账。来源：2026-03 的压测记录和财务的反馈。
- [2026-03-25] 试过把结算文件先写到对象存储、再让银行侧拉取（`s3_handoff` 分支），银行只认 SFTP，不支持对象存储，分支已删。来源：与三家银行的确认邮件。
- [2026-04-05] 直接对生产跑 `alembic upgrade head` 出过事故：autogenerate 把列改名生成成 drop + add，丢了一天的费率数据。此后每次迁移上线前必须先跑 `make migration-dryrun`，把生成的 SQL 交给 DBA 过目再执行，不要跳过这一步。
