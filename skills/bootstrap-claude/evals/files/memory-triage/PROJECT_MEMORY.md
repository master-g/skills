## 已验证的事实

<!-- 追加：确认过的决策和约束，每条一行：结论 + 原因 + 来源。同主题改写既有条目，不追加第二条。 -->

- [2026-08-04] CSV 第一行带 UTF-8 BOM，是为了让 Windows 版 Excel 双击打开时直接识别成 UTF-8：去掉 BOM 后财务反馈中文列名全是乱码，Mac 版 Numbers 认得 BOM，不受影响。来源：工单 `FIN-2231`，财务和运营两边都复现过。BOM 只写在第一块输出里，后面逐行追加的部分不能再带，否则 Excel 会在中间某一行显示一个看不见的怪字符，财务复制粘贴时才会发现。有人提议改成 GB18030 编码来绕开 BOM，但下游脚本全按 UTF-8 读，没采纳。
- [2026-08-25] 以 `=`、`+`、`-`、`@` 开头的单元格前面补一个单引号，防止 Excel 把用户填的备注当公式执行（CSV 注入）。负数金额也会被补引号，财务的导入脚本 `fin_import.py` 读金额列时会先去掉开头的单引号，已和脚本维护人确认，不用为金额列开例外。只补引号、不删字符，是为了让导出的内容能原样还原；运营曾建议直接去掉开头的等号，被财务否决，因为备注里的算式是他们要看的原文。单元格内容只有一个减号的情况也会补引号，这是预期行为。
- [2026-09-15] 导出文件名里的日期按 `EXPORT_FILENAME_TZ` 取（默认 Asia/Shanghai），不用服务器的 UTC：运营按北京时间找文件，之前凌晨 0–8 点导出的文件被当成前一天的，重复导了好几次。来源：运营群 2026-09-01 的反馈，改完后没再出现。文件内容里的时间戳仍然是带时区偏移的 ISO 8601，不受这个配置影响，下游脚本按偏移量自己换算。海外分公司要求按当地时间命名时，在请求里带 `tz` 参数覆盖，默认值不变。
- [2026-10-06] CSV 行尾固定用 `\r\n`（`csv.writer` 的 `lineterminator` 参数），这是 RFC 4180 的写法：下游 SAS 导入任务遇到裸 `\n` 结尾会把整份文件读成一行，报列数不符。来源：数据组 2026-09 的回复，他们暂时不打算改导入任务。Python 的 `csv` 模块默认就是 `
`，所以这里写出来只是为了让读代码的人知道这是有意为之，不要改成平台默认。单元格内部的换行保持 `
`，并由 `csv` 模块自动加引号，SAS 那边能正确识别。
- [2026-10-27] uvicorn 前面的 nginx 要配 `proxy_buffering off`，否则流式导出会先在 nginx 那里攒满再一次性下发，大表导出时浏览器 60 秒收不到首字节就断开，用户看到的是下载失败。来源：运维 `OPS-517` 的排查记录，预发和生产都已配好。只对 `/exports/` 路径关掉，其他接口仍保持默认，避免慢客户端占住 uvicorn 的 worker。同时把 `proxy_read_timeout` 调到 300 秒，长导出不会被 nginx 先掐断。

## 失败尝试

<!-- 追加：走不通的路径及原因，每条一行。 -->

- [2026-08-04] 试过用 `pandas.DataFrame.to_csv` 生成导出：30 万行的表占到 2.1 GB 内存，被容器 OOM 杀掉；pandas 还会把 `00123` 这类编号读成整数，丢掉前导零。放弃，改回标准库 `csv` 逐行写出，内存稳定在 80 MB 左右。当时也试过分块读再拼接，内存降下来了，但前导零的问题仍在，要逐列指定 `dtype=str`，维护成本太高。依赖里也因此去掉了 pandas 和 numpy，镜像小了 120 MB。
- [2026-09-15] 试过 `csv.QUOTE_NONNUMERIC`，想让数字列不加引号、方便下游直接求和。结果所有非数字字段都被加上引号，数据组的老版 Kettle 任务把带引号的空串读成两个引号字符，入库后一片脏数据。放弃，保持默认的 `QUOTE_MINIMAL`。数据组说 Kettle 任务明年会换成新的导入工具，到时候可以再评估要不要改引号策略。试的时候还发现数字列里的千分位逗号会被当成分隔符拆开，更说明不能依赖这个选项。
- [2026-10-27] 试过在 FastAPI 里加 `GZipMiddleware` 压缩导出响应，nginx 那层也开着 gzip，部分浏览器收到二次压缩的文件，下载下来是乱码。改成只在 nginx 压缩、应用层不压。来源：`OPS-529`，和运维一起抓包确认的。大文件下载的压缩比大约是 6:1，压缩放在 nginx 一层就够了；应用层再压只会多占 CPU，导出高峰时 uvicorn 的 CPU 曾经跑满。nginx 的 `gzip_types` 里已经加了 `text/csv`。
