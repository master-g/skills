# 项目记忆维护

`<skill>` 指本技能根目录。回写排在验证之后、提交之前，与本次改动进同一个提交；不提交的任务在结束前回写。

回写是提炼，不是记录。会话里发生的事绝大多数留在 Git、计划文档和证据目录里就够了；记忆只保存下次不看这些也必须先知道的东西。文件每次会话开头整读，所以它的每一行都在花下次会话的上下文。

## 写什么

只写代码、Git 和文档推导不出的内容。判定问句：**下次不看代码，30 秒内能从 `git log`、计划文档或证据目录推出来吗？** 能推出来的不写。commit SHA、"已提交／未 push／工作树 clean"、计划里已有的单元清单、验证跑了哪几条，都属于能推出来的。

每条写清 **结论 + 原因 + 来源或适用范围**：「换到 esbuild（webpack 在 CI runner 上 OOM，见 docs/adr/0007）」值得留，「换了打包器」和「今天把 esbuild 迁移提交为 a1b2c3d」都不值得。

| 小节         | 性质     | 内容                                                                                               |
| ------------ | -------- | -------------------------------------------------------------------------------------------------- |
| 已验证的事实 | 追加     | 本次确认的决策或约束（"auth 用 cookie 里的 JWT，不是 header"）                                     |
| 失败尝试     | 追加     | 走不通的路径和原因，防止下次重走；第二次踩到同一个坑就晋升到上下文文件「工作流与陷阱」             |
| 上次会话     | 整块改写 | 停在哪个分支，验证命令与实际结果，停在何处；任务细节只留一行指向证据目录；本次移出的条目各一行去向 |
| 下次运行     | 整块改写 | 接下来的计划与优先级，含仍受阻的项                                                                 |

追加类小节每条一行，`- [YYYY-MM-DD]` 前缀放在末尾。改写类小节每次只留最新一块，旧块直接删，历史由 Git 保存。

## 怎么写（compound 六步）

1. **筛**：把本次产出过一遍判定问句，留下的通常只有零到三条。
2. **查重与替换**：同主题已有条目就改写它，不追加第二条；结论被推翻就删旧条，不留「已失效」标记堆在旁边。
3. **晋升**：一条失败尝试或事实若每次会话都要先知道，或已第二次命中，它是指令而不是记忆——写进上下文文件的「工作流与陷阱」（做法 + 原因），记忆里删掉。晋升的去处要在上下文压缩后还在：根 `AGENTS.md`，或不带 `paths:` 的 `.claude/rules/*.md`（后者只有 Claude Code 读）。根文件接近 200 行时，把模块专属的内容搬去子目录文件，给规则腾位置。
4. **搬出**：一条长期知识写不进两行时，它已经是文档而不是记忆——搬进 `docs/`（或项目既有的知识目录），记忆里只留一行指针。已完结的旧会话同理压成一行或删除。
5. **交代去向**：每条从追加节消失的条目，在「上次会话」里写一行 `移出：<条目开头> → <去向>`。同主题的改写不用写。

   | 去向的写法                  | 含义                             |
   | --------------------------- | -------------------------------- |
   | `AGENTS.md「工作流与陷阱」` | 晋升，内容已写进该文件那一节     |
   | `docs/x.md`                 | 搬出，内容已写进该文件           |
   | `并入 <现存条目的开头>`     | 内容并进了记忆里另一条           |
   | `作废（原因）`              | 已被取代或已过期，写明被什么取代 |

   一行可以用 `；` 隔开几条的开头，共用一个去向。`check` 遇到没交代的条目会报 FAIL，并打印可以照抄的那一行。

6. **改写当前状态**：整块重写「上次会话」和「下次运行」。

```bash
python3 <skill>/scripts/memory.py add <workspace>/PROJECT_MEMORY.md \
  --section "失败尝试" --text "试过用 X 做 Y，因为 Z 放弃，改用 W（见 docs/adr/0009）"
python3 <skill>/scripts/memory.py add <workspace>/PROJECT_MEMORY.md \
  --section "上次会话" --text "feat/x @ a1b2c3d；make test 通过
补集成测试时停在 mock 网关；证据 local/requests/x/
移出：[2026-08-02] 部署前必须先跑 make smoke → AGENTS.md「工作流与陷阱」
移出：[2026-07-11] 临时跳过 integration job → 作废（#212 合并后已恢复）"
```

`add` 自动加当天日期（`--date` 可覆盖）；对改写类小节整节替换，`--text` 里的换行变成缩进的续行。直接编辑文件效果相同。上一次会话写了 `移出：` 却没有提交时，`add` 改写「上次会话」会自动保留那些行；直接编辑文件时自己留着。

## 完成标准

结束前运行：

```bash
python3 <skill>/scripts/memory.py check <workspace>/PROJECT_MEMORY.md
```

不通过不算回写完成。它查两件事：

- **门槛**：全文 ≤ 24 KB、单行 ≤ 300 字符、改写类小节各只有一块。
- **去向**：对比上一次提交，每条从追加节消失的条目都有一行去向，去向文件里确实有这条内容。

超限时按顺序处理：

1. `python3 <skill>/scripts/memory.py compact <file>` 把改写类小节裁成最新一块。
2. 晋升：把记忆里每次都要先知道的条目移进上下文文件。
3. 搬出：把同一主题的长条知识搬进 `docs/`，留一行指针。
4. 并入：合并同主题的条目，保留原因。
5. 作废：删掉已被取代或已过期的条目。仍然有效的内容走前三条。

脚本不会自动删追加类条目——盲删最旧的失败尝试丢的正是单位价值最高的内容。

有提交时，提交后 `git status` 里 PROJECT_MEMORY.md 没有未提交改动。
