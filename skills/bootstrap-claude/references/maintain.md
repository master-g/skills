# 项目记忆维护

`<skill>` 指本技能根目录。回写排在验证之后、提交之前，与本次改动进同一个提交；不提交的任务在结束前回写。

回写是提炼，不是记录。会话里发生的事绝大多数留在 Git、计划文档和证据目录里就够了；记忆只保存下次不看这些也必须先知道的东西。文件每次会话开头整读，所以它的每一行都在花下次会话的上下文。

## 写什么

只写代码、Git 和文档推导不出的内容。判定问句：**下次不看代码，30 秒内能从 `git log`、计划文档或证据目录推出来吗？** 能推出来的不写。commit SHA、"已提交／未 push／工作树 clean"、计划里已有的单元清单、验证跑了哪几条，都属于能推出来的。

每条写清 **结论 + 原因 + 来源或适用范围**：「换到 esbuild（webpack 在 CI runner 上 OOM，见 docs/adr/0007）」值得留，「换了打包器」和「今天把 esbuild 迁移提交为 a1b2c3d」都不值得。

| 小节         | 性质     | 内容                                                                     |
| ------------ | -------- | ------------------------------------------------------------------------ |
| 已验证的事实 | 追加     | 本次确认的决策或约束（"auth 用 cookie 里的 JWT，不是 header"）           |
| 失败尝试     | 追加     | 走不通的路径和原因，防止下次重走                                         |
| 上次会话     | 整块改写 | 停在哪个分支，验证命令与实际结果，停在何处；任务细节只留一行指向证据目录 |
| 下次运行     | 整块改写 | 接下来的计划与优先级，含仍受阻的项                                       |

追加类小节每条一行，`- [YYYY-MM-DD]` 前缀放在末尾。改写类小节每次只留最新一块，旧块直接删，历史由 Git 保存。

## 怎么写（compound 四步）

1. **筛**：把本次产出过一遍判定问句，留下的通常只有零到三条。
2. **查重与替换**：同主题已有条目就改写它，不追加第二条；结论被推翻就删旧条，不留「已失效」标记堆在旁边。
3. **搬出**：一条长期知识写不进两行时，它已经是文档而不是记忆——搬进 `docs/`（或项目既有的知识目录），记忆里只留一行指针。已完结的旧会话同理压成一行或删除。
4. **改写当前状态**：整块重写「上次会话」和「下次运行」。

```bash
python3 <skill>/scripts/memory.py add <workspace>/PROJECT_MEMORY.md \
  --section "失败尝试" --text "试过用 X 做 Y，因为 Z 放弃，改用 W（见 docs/adr/0009）"
python3 <skill>/scripts/memory.py add <workspace>/PROJECT_MEMORY.md \
  --section "上次会话" --text "feat/x @ a1b2c3d；make test 通过
补集成测试时停在 mock 网关；证据 local/requests/x/"
```

`add` 自动加当天日期（`--date` 可覆盖）；对改写类小节整节替换，`--text` 里的换行变成缩进的续行。直接编辑文件效果相同。

## 完成标准

结束前运行：

```bash
python3 <skill>/scripts/memory.py check <workspace>/PROJECT_MEMORY.md
```

不通过不算回写完成。门槛是全文 ≤ 24 KB、单行 ≤ 300 字符、改写类小节各只有一块。超限时按顺序处理：先 `python3 <skill>/scripts/memory.py compact <file>` 把改写类小节裁成最新一块；仍超限就回到「搬出」和「查重与替换」，合并同主题事实或搬进 docs/。脚本不会自动删追加类条目——盲删最旧的失败尝试丢的正是单位价值最高的内容。

回读本次写入：追加类小节原有条目一条不少（除非本次明确替换或搬出），改写类小节只剩本次一块。有提交时，提交后 `git status` 里 PROJECT_MEMORY.md 没有未提交改动。
