我不确定现在走到哪了、接下来该干什么。先盘点，再评估，最后给建议。只做评估与规划，输出后停下等我选。

## 1. 盘点证据

按任务相关性核对三类来源：

- **本会话** —— 对话历史与当前上下文：用户提出的目标、已经做过的操作、已验证与未验证的结论。
- **仓库状态** —— `git status -sb`（含未推送提交）、`git log --format='%h %ad %s' --date=short -20`、`git stash list`、`git worktree list`；有未提交改动时看 diff 摘要。
- **进度记录** —— 例如工作目录下的 `PROJECT_MEMORY.md`、`MEMORY.md`、`TODO.md`、`PLAN.md`、`NOTES.md`、`CHANGELOG.md`，`docs/plans/`、`docs/research/` 等计划与调研文档，会话交接（handoff）文件，Claude Code 的 auto memory 目录（`~/.claude/projects/<项目路径 slug>/memory/`，上下文里只注入 `MEMORY.md` 索引时，打开与当前目标相关的正文文件），以及 `CLAUDE.md` / `AGENTS.md` 中链接或描述的任何进度记录（「上次会话」「下次运行」「待办」之类的段落及其指向的文件）。`CONTEXT.md` 存在时用它的统一语言。
  - 先定位与当前目标有关的小节，追查其证据；记录很长时按章节检索，不因行数固定通读或派发子代理。
  - 仅对完成声明、记录矛盾和下一步依赖做必要复查，每条注明文件与小节。
  - 复查只用低成本、无副作用的只读手段（`git show`、搜索、查看文件或已有日志）；需要跑测试、构建等耗时或有副作用的检查才能确认的，标为「未验证」并列入下一步。

**完成条件**：三类来源各自有结论 —— 读到了什么，或明确写出「不存在」；每条声称完成的事项都带证据或明确标为「未验证」。

## 2. 状态评估

把盘点结果压成一张状态表：

- **目标** —— 这段工作到底要达成什么。以最新的用户原话为准（按对话顺序、commit 日期、文件修改时间判断新旧），较旧的记录标为待更新。
- **已完成** —— 每条附证据（commit、文件、测试输出、对话中的确认）。
- **进行中 / 卡住** —— 停在哪一步，卡在什么上。
- **未验证** —— 记录里声称完成但找不到证据的（memory 说做完了，git 里没有；对话里说测试通过，没看到输出）。单独列出，与「已完成」分开。

**完成条件**：每一条都带证据出处，或明确标为「未验证」。

## 3. 第一性原理规划

放下记录里原有的计划，从目标本身反推。原计划中由用户明确做出的决定（对话或记录里标明是用户拍板的取舍）视为约束，不在反推中推翻：

1. 目标达成需要哪些事实为真？
2. 其中哪些已经为真（有证据），哪些还没有？
3. 剩下的里，哪一件最大程度地消除不确定性或解除阻塞？

给出 1–3 条下一步，按顺序排列。每条写清：**做什么**（动词开头的具体动作）、**为什么先做它**、**完成标志**。建议只描述要做的事，不点名工具或技能。原计划与反推结果不一致时，说明差异；分歧只涉及未被证据支持的假设时，推荐反推的那个；触及用户已做的决定时，列出分歧与证据，交给用户定。

## 4. 输出并停下

按「现状 → 未验证与分歧 → 下一步」三段输出，总长控制在一屏内。输出后停下，等用户选定再动手。
